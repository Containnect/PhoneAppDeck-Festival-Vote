# PhoneAppDeck Festival Vote — AI開発教育教材（Phase 2）

**目的**：GitHubのボタン操作ではなく、**設計 → 試作 → 検証 → 改善**の繰り返しが便利な理由を学ぶ。

## まず動かしてみる

- このフォルダの `index.html` はHTML/CSS/JavaScriptだけで動くスマホ対応の試作品。外部ライブラリ、APIキー、DB、ビルドは不要。
- PCではブラウザで `index.html` を開ける。スマホではPhase 3のGitHub Pages公開、または先生が用意した公開URLから試せる。**GitHub上のファイル表示だけではWebアプリとして動かない**。
- ひとり1端末の投票ではなく、**同じブラウザ内だけ**の投票。友達の端末の票は合算されない。リセットは体験用。
- このコードは教材の初期状態。AIへの指示や改善点を自分で考えて書き換え、PRで変更を確認する。

## 4段階の体験（授業45〜50分×2コマ程度の目安）

### 1. 設計（15分）
対象は「文化祭を訪れる人」。最初の仕様を「選択肢が3つある」「1つ選ぶ」「選択結果を見る」とする。次の受入条件を生徒自身が書く。

- A: スマホで選択肢を押せる
- B: 投票後に選んだ項目が分かる
- C: ページを読み込み直しても、この端末では選択が残る（保存が許可されている環境）

**問い**：この3つができれば「最初の試作品」は完成？ 本番運用に足りない条件は？

### 2. 試作（15分）
上の初期版をPADでプロジェクトとして確認する。対応するAI開発ツールに、変更点を**小さく一つずつ**伝える。例：

> 文化祭投票Webアプリの画面で、選択肢を「展示」「カフェ」「ステージ」に変えてください。投票の保存や表示が壊れていないかも確かめてください。変更はレビューできるPRにしてください。

**問い**：AIの返答が「完成」でも、本当に受入条件を満たすか？

### 3. 検証（15分）
同じURLを友達に共有し、**説明せずに操作**してもらう。3つの受入条件をチェックし、観察した事実と改善案を分けて記録する。

| 受入条件 | 期待 | 実際 | 判定 |
|---|---|---|---|
| A | 選択できる | （記入） | OK/NG |
| B | 選択結果が分かる | （記入） | OK/NG |
| C | リロード後も残る | （記入） | OK/NG |

**気づきの例**：「友達も投票できたが自分の画面の票数は増えない」。これはこの教材の仕様通りであり、共有集計にはサーバー等が要るという設計上の発見。

### 4. 改善（次のコマ）
検証で見つかった**一件だけ**をIssueにして優先度と受入条件を書き、AIに修正を依頼する。PADでPRの差分とテスト結果を確認し、再び友達に試してもらう。

**Issueの例**
- 問題：投票が終わった後、どこを確認すればよいか分からない
- 根拠：試した3人のうち2人が結果を探して迷った
- 受入条件：投票直後に結果見出しが画面内で見えること
- 対象外：共有DB、本番投票

**問い**：改善で別の動作が壊れなかった？ なぜPR・履歴が役立つ？

## 学習成果（操作できたことではなく理由を説明できること）

1. なぜ試作前に受入条件を決めたか。
2. なぜAIが生成した画面を自分と友達で検証したか。
3. なぜ改善をIssueにまとめ、小さく修正して差分を確認するか。
4. 改善の前後で何が良くなったかを具体的に述べられるか。

**評価用記録**：最初の仕様、検証の事実、一件のIssue、PRの変更理由、再検証結果（個人情報は記載しない）。

## AI活用とPADの役割

AIはコードの作成と修正を補助する。PADは既存のGitHubプロジェクト・PR・Actions等の確認に使う。AIへの指示そのものは対応する外部サービスで行う場合がある。生徒は「なぜ・何を作る・何を試す・何を直す」を判断する。

## 運用上の注意

- **教材はローカル投票**。みんなの票を同時集計するシステムではなく、実際の投票や個人情報収集には使わない。
- 学校の端末・GitHub/AIサービス利用条件、年齢・費用・利用規約・プライバシーを教員が事前確認する。生徒アカウントがなくても先生の端末と共有URLで検証活動は可能だが、PR操作の個人体験にはアカウント・権限が必要。
- GitHub Pagesによる公開設定とPADの公開UI簡素化はPhase 3。今は自動公開設定を同梱していない。
- 共有集計・本人認証・重複投票防止は発展課題。Firebaseなどの構成と権限制御が必要。
- **PADから「このサンプルを使う」を利用するには、GitHubリポジトリ設定の Template repository を有効にする必要がある。**本リポジトリが教材原本。PAD側の公式サンプル登録にはGitHubの **Template repository** 設定が必要。
