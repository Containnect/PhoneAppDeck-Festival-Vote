# Festival Vote — 文化祭投票アプリ

スマホで動く投票アプリを、AIと一緒に作って育てよう。

このサンプルでは、アプリを作るだけでなく、**設計 → 試作 → 検証 → 改善**という開発サイクルを体験できます。最初から完璧に作る必要はありません。友達に使ってもらい、気づいたことを一つずつ改善してみましょう。

## どんなアプリ？

3つの文化祭企画から一つを選ぶWebアプリです。**最初の状態では投票を確定する機能が未完成**。AIと一緒に最後の仕事を仕上げ、公開して友達に使ってもらいましょう。

- スマホのブラウザで操作できます。
- 投票の保存処理と結果表示は用意されていますが、確定ボタンとの接続が残っています。
- 何度でも試せるよう、投票をリセットできます。

**注意：投票結果は自分のブラウザ内だけに保存されます。** 友達の票は合算されません。これは開発練習用のサンプルであり、実際の文化祭の投票管理には使えません。

## はじめかた

1. PhoneAppDeck（PAD）の公式サンプルから **Festival Vote** を選び、「このサンプルを使う」で自分のリポジトリを作成します（GitHubへの接続が必要です）。
2. `index.html` がアプリ本体です。HTML・CSS・JavaScriptだけで動き、追加のパッケージやAPIキーは不要です。
3. Webアプリをブラウザで開いて、投票を試してみましょう。PCでは `index.html` を直接開けます。スマホで友達にも試してもらうには、GitHub Pagesなどで公開する必要があります（公開設定は別途必要です）。
4. [引き継ぎメモ](.phoneappdeck/handover.md)で構成と残作業を確認し、自分のリポジトリで最後の仕事をIssueにします。AIに実装を依頼し、PRで変更を確認して動かしてみましょう。

Web公開するにはリポジトリの Settings → Pages で **Source: GitHub Actions** を選び、Actionsの `Publish website (GitHub Pages)` を実行します。設定後は main の更新で再公開されます。 

GitHubのコード画面で `index.html` を開くだけでは、アプリとして操作できません.公開したURLまたはブラウザで実行してください。

## やってみよう：引き継ぎ → 完成 → 公開 → 検証 → 改善

### 1. 設計：何ができたら完成？

「企画を一つ選べる」は実装済みです。「確定後に自分の結果が分かる」「ページを再読み込みしても選択が残る」を残りの完成条件にします。自分ならどんな機能を追加したいかも考えてみましょう。

### 2. 試作：AIに小さな変更を頼む

たとえば、こんなふうに依頼できます。

> 文化祭投票アプリの `index.html` を読んで、投票確定ボタンを完成させてください。既存の `saveVote` と `render` を活用し、確定後の保存と結果表示を実現してください。変更点を確認できるPRにしてください。

一度にすべて変えるのではなく、まず一つだけ変えて動作を確かめるのがコツです。

### 3. 検証：友達に使ってもらう

友達に説明せずに使ってもらい、操作に迷わないか、投票結果が分かりやすいかを観察します。自分が思ったことと、実際に起きたことは分けて記録しましょう。

| 確かめること | 期待した動作 | 実際の動作 |
|---|---|---|
| 選択肢を押す | 一つ選べる | （記入） |
| 投票する | 自分の選択が見える | （記入） |
| 再読み込み | 同じブラウザで選択が残る | （記入） |

別の端末の投票が反映されないことに気づいたら、それも大事な発見です。全員の票を集計するには、データの共有方法を改めて設計する必要があります。

### 4. 改善：問題を一つ解決する

見つかった問題を一つ選んでIssueに記録し、AIに修正を頼みます。PRでどこが変わったかを確認し、もう一度友達に使ってもらいましょう。

Issueの書き方の例：

- **問題：** 投票後に結果がどこにあるか分かりにくい
- **観察：** 3人中2人が結果を探して迷った
- **完成条件：** 投票直後に結果が見つけやすい
- **今回はやらないこと：** 全員の投票集計

「最初に完成条件を決める」「人に試してもらう」「変更履歴を残す」がなぜ便利なのか、実際の体験から考えてみてください。

## 次に作りたい機能は？

投票項目の追加、デザインの改善、集計結果の見せ方など、自分のアイデアで発展させてみましょう。みんなの投票を共有する機能にはデータベースやアクセス制御が必要になるため、もう一段階高度な課題です。

## 安全に使うために

公開リポジトリに名前などの個人情報、パスワード、APIキーを保存しないでください。学校で使う場合は、GitHubやAIサービスの年齢条件、学校の利用ルール、公開範囲を確認してください。

詳しい動作確認項目は [TESTING.md](TESTING.md) にまとめています。
